# デスクトップ版の移行設計

作成日：2026-10-27。状態：初版の設計と実装状況。以下は旧版との比較・提案を記した初版で、採用した保存方式・入力条件・実装上の細部は[ADR 0005](decisions/0005-desktop-implementation.md)と、保存先・補助操作を変更した[ADR 0007](decisions/0007-portable-desktop.md)を正とする。PC互換コア、保存・移行・復元、2タブ、main/preloadの限定API、コピー期限を実装した。Windows実動作は未確認。

## 前提と決定済みの範囲

- ユーザー指定：デスクトップから設計を進め、旧PC版の仕様・UIをほぼそのまま移行する。
- ユーザー確認済み：新PC版のデータを旧Android版へ戻す必要はない。新Android版への移行後に利用できればよい。
- Electron＋React＋TypeScript、Windowsでのアプリ検証、WSLでの開発・ローカル検証は既存方針を維持する。
- 旧PC版の「パスワード生成」「サービス登録」の2タブと操作順を基準にする。サービス編集・削除・検索、クラウド同期、自動入力、新生成方式は初回移行の範囲に含めない。
- 生成結果を画面に表示せずコピーする。マスターと生成結果は保存しない。サービス先での変更操作はユーザーが行う。

以下の細部は、旧挙動の調査結果と移行時の提案を分けて記す。保存方式・入力制限などの提案は、実装前に確定する。

実装時更新：ユーザー承認により平文JSON、新規8〜64文字、名前の前後空白除去と制御文字拒否、記号の初出順重複除去を採用した。履歴解除時の最新へのリセット、切替時のマスター消去、salt追加確認、所有内容だけのコピー消去も実装した。補助操作はメニューの代わりに上部の小さなボタンへ配置した。旧Androidとの差異は[別紙](legacy-mobile-differences.md)、具体的操作と未実施のWindows検証は[検証手順](desktop-validation.md)へ記録する。

## 調査の根拠と限界

旧PC版のコミット`9840d111cab0f0634cfaa1a50dd6c81da28cafc1`をWSL上で静的に確認した。対象は`PasswordManager.scala`、`GenerateTab.scala`、`RecordTab.scala`、`Record.scala`、`Records.scala`、`PasswordGenerator.scala`、`ClosableTab.scala`、`MyAlert.scala`とREADME。[固定ソース](https://github.com/ikegami5/passwordManager/tree/9840d111cab0f0634cfaa1a50dd6c81da28cafc1/src/main/scala/passwordManagerMain)、[既存調査](legacy-projects.md)を参照。

今回、旧GUIの起動・スクリーンショット採取・実データの読込・旧テストの再実行は行っていない。配置・文言・初期値はソースに基づく。フォント、実際のウィンドウ寸法、OSテーマによる見た目は未確認であり、ピクセル単位の一致は要件にしない。新アプリの現在の900×620は環境確認用の寸法で、旧版の寸法ではない。

## 画面設計

単一ウィンドウ、上部の閉じられない2タブ、白地の標準的なフォームとする。初期タブは「パスワード生成」。新しいサイドバーや一覧画面は加えない。説明文や警告の口調も原則引き継ぐ。

### パスワード生成タブ

下図のサービス名と説明は架空の例。枠は領域を示し、表示寸法を規定しない。

```text
┌ パスワード生成 ┬ サービス登録 ──────────────────────┐
│ パスワードを生成するサービスを選んでね                │
│ [ Example service                              ▼ ] │
│ ┌────────────────────────────────────────────────┐ │
│ │ テスト用サービスの説明（読取専用・複数行）      │ │
│ └────────────────────────────────────────────────┘ │
│ [パスワード変更] □以前までのパスワードを使用する      │
│                    [現在のパスワード           ▼]   │
│ マスターパスワード(8文字以上)を入力してね              │
│ 注意：マスターパスワードは復元不可能だよ               │
│ 変更も基本的にできないから気をつけてね                 │
│ [ ●●●●●●●●                                      ] │
│ コピー・消去状況（緑色の通知）               [生成]   │
└────────────────────────────────────────────────────┘
```

履歴の選択欄はチェック時のみ表示する。通常の操作順は「サービス選択→マスター入力→生成→貼り付け」で変えない。

| 要素・操作   | 旧PC版の挙動                                                | 移行設計案                                                                          |
| ------------ | ----------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| サービス選択 | 保存順、初期選択は先頭                                      | 維持。内部の識別にはサービス名でなくIDを使用                                        |
| 説明         | 読取専用TextArea                                            | 維持。スクロールと文字列選択を可能にする                                            |
| サービス切替 | 履歴選択を最新へ戻し、履歴欄を隠す                          | 維持。マスター入力は切替時に消去する改善案                                          |
| 履歴         | 最新が「現在のパスワード」、以降「1個前のパスワード」等     | 維持。チェック解除時にも最新へ戻す改善案。旧版は欄を隠すだけで過去の選択が残る      |
| マスター     | 半角英数字8文字以上、伏字、送信後は成否にかかわらず空にする | 維持。trim・Unicode正規化・自動変換はしない。誤入力かどうかを判定できる機能ではない |
| 生成結果     | 本文に表示せずコピー                                        | 維持。コピー成功後だけ成功通知を表示                                                |
| 通知         | 緑色18pt、貼り付け方法と消去までの秒数                      | 同じ位置と内容を基準にする。コピー失敗・生成失敗はエラー表示                        |
| データ0件    | 生成時に登録を促す                                          | 案内を常時表示し、生成・変更・履歴選択を無効化。登録タブへ移動できる                |

「生成」は処理中に再実行できない。マスターを含む入力は送信後すぐフォームから除去し、失敗時も再入力する。タブ移動時もマスターを消去する提案とする。サービス選択・タブ移動で、すでにコピーした内容の期限は延長しない。

### サービス登録タブ

```text
┌ パスワード生成 ┬ サービス登録 ──────────────────────┐
│ サービス名（区別しやすい名前を入れてね）              │
│ [                                                ] │
│ ログイン時に必要な情報など（アカウント名とか）        │
│ ┌────────────────────────────────────────────────┐ │
│ │                                                │ │
│ └────────────────────────────────────────────────┘ │
│ パスワードに含める条件                              │
│ ☑大文字を1文字以上含める ☑数字を1文字以上含める      │
│ □記号を1文字以上含める                              │
│ 使える記号を入力してね… [                         ] │
│ パスワードの最大文字数：[        ] 文字              │
│                                            [登録]  │
└────────────────────────────────────────────────────┘
```

- サービス名・説明・文字数は初期値を空とし、大文字と数字はON、記号はOFF。小文字は常に必須で、追加のチェック欄を作らない。
- 記号欄は記号ON時に表示し、ON/OFF変更時に入力を消す旧動作を維持する。空白・コンマ・バックスラッシュ・円記号等の受付範囲は、旧正規表現から固定ケースを作って確認する。
- 登録は一覧の末尾に追加する。永続化成功後に成功ダイアログを表示し、フォームを初期化、生成側の先頭サービスを選択する旧動作を維持する。タブは自動移動しない。
- 保存失敗時は登録完了にせず、登録フォームを残す。二重登録を防ぐため保存中は再送を無効化する。
- 説明の改行は扱えるようにする。サービス名に改行・制御文字を許すか、名前前後の空白をどう扱うかは下記の入力制限と一緒に確定する。

### 寸法・入力操作

余白は旧版の20を基準に、説明欄と入力欄を縦方向に並べる。初回実装は現在の900×620を出発点とする提案。Windowsの表示倍率100%・150%・200%で、文字切れやボタンの隠れを確認して最小寸法を決める。高さが不足した場合はフォーム領域をスクロール可能にする。

タブ・チェックボックス・入力欄・ボタンは標準のキーボード操作に対応し、Tab順は表示順とする。入力欄にラベルを関連付け、通知は色以外の文章でも伝える。Enterでの送信は初期移行では追加せず、旧版と同じボタン操作を基準にする。

## 操作ごとの処理

### 起動と読込

`起動 → 保存読込中 → 利用可能（0件も含む） / 読込エラー`を明確に分ける。読込エラーはデータ0件として扱わず、登録・salt追加・上書きを禁止する。再読込と、バックアップを選んで検証する導線を用意する。復元を実行する前に件数・履歴件数と上書き対象を確認する。

ファイルが存在しない初回起動だけを新規開始として扱う。アクセス拒否、JSON破損、未対応バージョンは新規開始にしない。最初の保存前に空ファイルを作る必要はない。

### 生成とコピー

1. main側でもサービスID・履歴ID・マスターの入力条件を検証する。UIのチェックだけには依存しない。
2. 保存済みの生成条件とsaltをmainが取得し、互換コアで生成する。rendererに条件を改ざんさせない。
3. コピーに成功した時刻から30秒の期限をmainで管理し、UIには結果文字列を返さずコピー状態・期限だけ返す。
4. 再生成成功時は古い期限を破棄し、新しいコピーの期限へ置き換える。失敗した再生成では、先行するコピーの期限を取り消さない。
5. 101候補を試しても生成できない場合は、失敗を表示する。条件・長さ・saltを自動変更しない。

クリップボード操作は直列化し、非同期の完了が前後して古い通知や消去が新しいコピーを壊さないようにする。main側には処理の世代番号を持たせる。導入済みElectron 45の型定義では`readText`／`writeText`はPromiseであり、完了と失敗を待って扱う。

### パスワード変更（salt追加）

旧版はボタン押下だけで即時追加・保存する。移行では誤操作対策として「新しいパスワード用の履歴を追加します。サービス側のパスワードは変更されません」という確認を挟む提案とする。UIのボタン名は維持する。

確認 → 新salt生成 → 履歴先頭へ追加した候補データ作成 → 保存 → UI更新の順に進める。成功後は現在のパスワードを選択し履歴欄を隠す。過去salt・条件・記号順は保持する。失敗時は旧状態を維持し、未保存の新saltで生成させない。サービス側の変更に失敗した場合も過去履歴から元のパスワードを再生成できる。

### クリップボードの消去

旧版は30表示から0表示の次のtickで無条件に空にするため、後で他アプリからコピーした内容も消す。改善案は「コピー成功から約30秒後と通常終了時に、直近にアプリがコピーした文字列と現在のテキストが一致する場合のみ消去する」。タイマーの残り回数ではなく期限から残秒を計算し、スリープ復帰時にも期限超過を確認する。

比較に必要な直近の生成結果はmainの一時メモリだけに保持し、期限終了・所有内容の変更確認・終了時に参照を破棄する。マスターはキャッシュしない。JavaScriptの文字列を物理的に完全消去する保証はしない。

他アプリの内容に変わっていれば上書きせず、通知は「クリップボードの内容が変更されました」とする。消去失敗時に成功表示はしない。同一文字列の再コピーや比較直後の他アプリの書込みは完全には区別できず、OSのクリップボード履歴・外部アプリの記録・強制終了時の消去も保証しない。この改善はWindows上で確認してから採用を確定する。

## データ・保存・移行の設計案

### 共通モデル

| 項目                          | 意味・不変条件                                                       |
| ----------------------------- | -------------------------------------------------------------------- |
| `formatVersion`               | ファイル全体の形式。初版案は`1`。未知の版を書き換えない              |
| `records`                     | サービス配列。表示順を保持                                           |
| `id`                          | サービスの内部識別子。名称の変更等に依存させない                     |
| `serviceName` / `serviceInfo` | サービス名と説明。生成入力には含めない                               |
| `generatorVersion`            | 例：`legacy-pc-v1`。ファイル形式の版とは独立。移行時に変更しない     |
| `hasCapital` / `hasNumeral`   | 大文字・数字の必須条件                                               |
| `symbols`                     | 順序・重複を保持する文字列。保存済み値のソート・重複除去を禁止       |
| `passwordLength`              | 保存済みの長さ。インポート時に丸めたり下限へ引き上げたりしない       |
| `salts`                       | `{ id, value }`の配列、最新が先頭。旧ファイルからは1回だけ順序を反転 |

新規saltは暗号学的乱数から英数字64文字を偏りなく生成する案。旧saltの文字列はそのまま保持する。取込時に生成日時を推測しない。マスター、生成結果、コピー通知の状態はこのモデルに含めない。

`legacy-pc-v1`は実装・fixtureで旧PC版との一致を確認してから使用する識別名の案。スマホ版由来の差異が見つかったデータを、確認なしにこの版へまとめない。共通コアを使っても、Android側の互換性確認は別途行う。

### 保存方式

提案はバージョン付きUTF-8 JSONとし、Windowsのアプリ専用保存領域（Electronの`userData`配下）を使う。カレントディレクトリや実行ファイル配置先から独立させ、画面の補助メニューから保存場所を確認できるようにする。アプリ名による保存先の変動を避けるため、保存先の名前を実装時に固定して記録する。

JSONは暗号化ではない。平文を続けるか、設定データを暗号化するかは未決定。暗号化する場合は鍵管理・解除操作・バックアップ・端末間移送を併せて決め、この保存案を更新する。生成用マスターを自動的に保管用の鍵へ流用しない。

保存要求をmainで直列化し、単一起動に制限する。候補全体の検証 → 既存の正常ファイルをバックアップ → 同じディレクトリの一時ファイルへ書込み・flush・close → 置換 → メモリ/UIの確定、を基本とする。Windowsでの置換失敗・ウイルス対策ソフトによるロック・空き容量不足を試験し、成功前には旧ファイルと旧メモリ状態を維持する。起動時は残った一時ファイルを正本へ自動昇格させない。

バックアップも機密データとして扱う。提案は初回移行前のコピーを別途残し、通常保存時は直前の正常版1世代を保持する。自動削除と長期世代管理は追加要件とする。破損した正本で正常なバックアップを上書きしない。

### 旧data.txtの取り込み

1. ユーザーがファイル選択を行う。起動時の自動探索や旧アプリのファイルへの直接保存は行わない。
2. mainが選択したファイルを読み、共通コアが独自形式として解析する。標準CSVとして解釈しない。
3. プレビューはサービス件数・履歴件数・診断を中心に表示し、salt・生成結果を表示しない。エラーには行番号と理由を出し、行原文や説明全文をログへ出さない。
4. 全件検証に成功した場合だけ取り込みを確定できる。部分的な成功を黙って保存しない。末尾改行は許容し、途中空行・欠損salt・重複名・範囲外長さ・曖昧なエスケープは検出して扱いを明示する。
5. 初回は空の保存先への一括取り込みを対象とする。既存データとのマージは初期範囲に含めず、データがある場合は取り込みを止める。復元による置換とは分ける。
6. 旧ファイルは上書きしない。元ファイルのバイト列を保つバックアップを新アプリ側に確保してから新形式を保存し、失敗時は完了扱いにしない。

取込済みレコードをフォームで再登録しない。旧読込におけるtrimとエスケープ復元を適用した値を基準とし、さらに正規化しない。異常値を補正する必要があれば、その条件と影響を記録して確認する。

旧Android形式への書き出しは不要。新Androidへの受け渡しは、同じ版のファイルを明示的にエクスポート・インポートする案とし、自動同期や実行中の共有ファイル直接編集は初期範囲に含めない。暗号化の決定によって受け渡し形式を確定する。

Androidの初回範囲は選択・生成・コピーと確認済み（2026-10-27）。[Android移行設計](android-design.md)では、PCを編集元として全件置換による再取り込みを提案する。共通モデルのID・生成版・履歴順を維持し、Android側で登録・salt追加を行わない。転送・暗号化の詳細は両設計で合わせて確定する。

## Electronと共通コアの責務

| 層       | 担当                                                                                               |
| -------- | -------------------------------------------------------------------------------------------------- |
| renderer | 2タブ、フォーム、選択、コピー状態とエラーの表示。マスターは送信に必要な間だけ保持                  |
| preload  | 用途を限定した型付きAPIの公開。汎用IPC送信・Node・ファイル操作・任意クリップボード操作を公開しない |
| main     | 保存場所、ファイル選択・読込・保存・バックアップ、乱数、生成実行、クリップボードと期限、単一起動   |
| core     | 互換生成、データ型・検証、旧形式解析、新形式の検証・変換。Electron・ファイルI/O・UIへ依存しない    |

IPC案：`loadState()`、`registerService(input)`、`appendSalt(serviceId)`、`generateAndCopy(serviceId, saltId, master)`、`previewLegacyImport()`、`commitLegacyImport(token)`、`exportData()`、`previewRestore()`、`commitRestore(token)`。名前は実装時に確定する。ファイル選択はmainで行い、rendererから任意パスを渡させない。プレビューのtokenはmainで保持する解析結果へ紐づけ、確認後に別内容へすり替わらないようにする。

公開状態にはサービスID・名前・説明・履歴ラベル等、画面に必要な項目だけ含める。saltの値・生成結果・マスターを返さない。コピー状態の通知は期限と状態のみとし、画面再読込後もmainから再取得する。

各呼出は送信元のウィンドウ・メインフレーム・想定URLを検証し、入力型・サイズ・ID・状態を検証する。二重の登録・salt追加・古い状態に基づく操作を防ぐ。エラーは型付きのコードと必要な文言へ変換し、入力値や例外全文をUI・ログへ流さない。開発時も秘密をconsoleへ出さない。既存の`nodeIntegration: false`、`contextIsolation: true`、`sandbox: true`とCSP、外部遷移の拒否を維持する。

実装した配置：`packages/core/src/legacy/`に互換生成・旧形式解析、`packages/core/src/model/`に形式と検証、`apps/desktop/src/main/`に保存・クリップボード・IPC、`apps/desktop/src/renderer/src/`に2タブと状態管理を置く。Reactのローカル状態とフックで管理し、新しい状態管理ライブラリは導入していない。

## 旧仕様からの変更案と未決定事項

| 論点                 | 提案・確定に必要なこと                                                                                                                      |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| 保存形式・暗号化     | JSON＋アプリ専用領域を提案。平文継続か暗号化するかを実装前に確認                                                                            |
| 新規登録の長さ       | 旧版は4以上、64超を64へ丸める。新規は明示的な下限〜64とし、範囲外は拒否する案。条件別下限の具体値は未決定。既存値は変更しない               |
| 短い長さの限界       | 必須文字種数以上でも101候補での成功保証はない。下限の設計と生成失敗処理を別々に検証                                                         |
| 新規登録の記号順     | ScalaのSet順を新規に再現する必要性を検討。案は入力の初出順で重複除去し、確定した文字列を保存。既存値には適用しない                          |
| 名前の入力           | 新規は空白のみ・改行・制御文字を拒否する案。trimの有無、大小文字とUnicode正規化の違いを同名とするかを確定。取込済みの名前は勝手に変更しない |
| 履歴とマスター       | チェック解除時に最新へ戻す。サービス・タブ切替でマスター消去を提案                                                                          |
| salt追加             | 確認ダイアログを提案。生成失敗時の自動追加はしない                                                                                          |
| コピー消去           | 約30秒、内容一致時のみ消去を提案。Windows試験と限界の確認が必要                                                                             |
| 補助操作             | 2タブは維持し、ファイルメニュー等へ取り込み・書き出し・復元・保存場所表示を追加する案                                                       |
| PCと旧スマホの不一致 | PC互換をデスクトップの基準にする。差異を具体的入力で記録し、新Androidの扱いは確認する                                                       |
