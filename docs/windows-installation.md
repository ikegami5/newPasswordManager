# Windows正式版のインストール・更新

更新日：2026-10-28。ユーザーからPC・Androidの動作確認と本番用JSON移行の完了報告あり。本書はWindows用ZIPの導入・更新手順です。今回の旧データ移行タブへの変更後の画面と、再作成した正式配布物の実機動作は別途確認します。Android正式版は[専用手順](android-installation.md)を参照してください。

## 1. ZIPをコピーして展開する

現在はインストーラーではなく、ZIPを展開して使う形式。

1. WSLのプロジェクト内にある`apps/desktop/dist/New Password Manager-0.1.0-win.zip`を、Windowsの書込み可能なフォルダ（例：ドキュメント内の専用フォルダ）へコピーする。
2. WindowsのエクスプローラーでZIPを右クリックし、「すべて展開」を選ぶ。
3. 展開先に`New Password Manager.exe`、`resources`などがあることを確認する。タイトルバーとエクスプローラーのEXEには、青い円と白い鍵のアイコンを設定している。Windows版はコード署名なしのZIP。EXEだけを別の場所へ移動せず、展開したフォルダ全体を保持する。

Windows側にNode.js・npm・Java・Android SDKを別途導入する必要はない。ZIPはWSLで作成済みなので、今回の確認だけなら再ビルドも不要。

同梱するElectronの言語ファイルは日本語・英語のみ。アプリの画面文言は日本語のまま。

WindowsからWSL側のZIPを探す場合、エクスプローラーのアドレス欄に次の形式で入力できる。`<WSLのディストリ名>`と`<Linuxユーザー名>`は自分の環境の値に置き換える。

```text
\\wsl.localhost\<WSLのディストリ名>\home\<Linuxユーザー名>\projects\newPasswordManager\apps\desktop\dist
```

自分でZIPを作り直す場合は、[READMEのWindows用ビルド手順](../README.md#windows向けの検証用zip)を使う。WSLの開発環境の導入手順もREADMEにある。

## 2. 本番用JSONを引き継いで起動する

1. 現在のPC版を終了する。EXE隣の本番用`data.json`を、旧フォルダとは別の場所にもコピーして保管する。
2. 新しいZIPを別フォルダへすべて展開する。EXEだけを差し替えない。
3. 移行済みの`data.json`を新しいEXEと同じフォルダへコピーする。エージェントは本番ファイルを読み込まず、このコピーは利用者が行う。
4. 新しい`New Password Manager.exe`をダブルクリックして起動する。Node.jsや開発サーバーは不要。
5. サービスと履歴が表示されることを確認する。確認が済むまで旧フォルダとJSONの保管コピーを残す。

通常の保存先はEXE隣の`data.json`のままで、保存形式・生成処理は変更していない。本番JSONへの移行は完了しているため、「旧データ移行」は使用しない。初回で空に見える場合は、アプリを終了してJSONの配置先を確認する。元JSONを残したまま確認し、空データで上書きしない。

画面は「パスワード生成」「サービス登録」「旧データ移行」の3タブ。普段は最初の2つを使う。旧移行タブの取り込みは、登録データが0件の場合だけ実行できる。

## 架空データで追加確認する場合

以下は任意の開発検証手順。本番用JSONを引き継ぐ通常導入では実行不要。

### テスト専用の保存先で起動する

最初は架空データを使い、通常の保存データと分離する。

1. 展開先フォルダをWindowsのエクスプローラーで開く。
2. フォルダ内の余白を右クリックし、「ターミナルで開く」などからPowerShellを開く。PowerShellのカレントディレクトリが、EXEのある展開先になっていることを確認する。
3. 次を実行する。

```powershell
& '.\New Password Manager.exe' --newpm-test-profile=first-check-20261027
```

タイトルに「テスト用」と表示されることを確認する。保存先はWindowsの一時領域内の`new-password-manager-tests\first-check-20261027`で、通常は`%TEMP%`から探せる。初回はサービス0件となる。保存場所を表示するボタンはない。

同じプロファイル名で再起動すると同じテストデータを読み込む。最初からやり直す場合はアプリを終了し、`first-check-20261027-2`など、未使用の名前に変えて起動する。プロファイル名は英数字・ハイフンの1〜64文字。

### 登録・生成・コピーを確認する

1. 「サービス登録」タブで、次の架空データを入力する。

   | 項目         | 入力例               |
   | ------------ | -------------------- |
   | サービス名   | `動作確認用サービス` |
   | 説明         | `架空データです`     |
   | 大文字・数字 | 両方ON（初期値）     |
   | 記号         | ONにし、`!@#`を入力  |
   | 最大文字数   | `16`                 |

2. 「登録」を押し、成功ダイアログとフォームの初期化を確認する。登録タブのままで正常。
3. 「パスワード生成」タブを選び、登録したサービスと説明が表示されることを確認する。
4. 架空のマスター`TestMaster123`を手入力して「生成」を押す。マスター欄が空になり、コピーと残り秒数の通知が出ることを確認する。
5. 30秒以内にWindowsのメモ帳などへ`Ctrl+V`で貼り付ける。生成結果はアプリ画面には表示されない。16文字で、小文字・大文字・数字・指定記号を含むことを確認する。
6. 同じマスターと履歴で再生成し、同じ文字列になることを確認する。登録時のsaltは毎回新規作成されるので、別の登録・別のプロファイルの結果とは比較しない。

生成から貼り付けまでの間に別の文字列をコピーすると、クリップボードの内容が置き換わる。最初の確認ではマスターを手入力し、生成後すぐ貼り付ける。

### 消去・履歴・再起動を確認する

- **30秒後の消去**：生成後、アプリの通知が消去済みに変わるまで待つ。貼り付け先の文字を削除して再度`Ctrl+V`し、生成結果が貼り付かないことを確認する。すでにメモ帳へ貼った文字やOSのクリップボード履歴まで消す機能ではない。
- **他アプリのコピー保護**：生成直後、メモ帳で`clipboard-check`という架空文字列をコピーする。元の期限を過ぎた後も、それを貼り付けられることを確認する。
- **履歴追加**：「パスワード変更」を押し、確認後に履歴を追加する。サービス先への変更操作は行われない。「以前までのパスワードを使用する」にチェックし、「1個前のパスワード」と同じマスターで、追加前の結果を再生成できることを確認する。
- **再起動**：アプリを終了し、上記と同じコマンドで起動する。サービス・説明・履歴が残ることを確認する。
  設定・salt履歴は保存先の`data.json`へ平文で保存される。保存失敗に備え、直前の正常版は`data.json.bak`へ自動保存する。マスターと生成結果は保存しない。アプリからのバックアップ復元・エクスポート機能は設けていない。

### 旧形式の取り込みを確認する場合

登録済みの保存先には旧形式を取り込めないため、アプリを終了して、さらに別の未使用プロファイルで起動する。

```powershell
& '.\New Password Manager.exe' --newpm-test-profile=compat-check-20261027
```

WSLの`packages/compatibility-fixtures/pc/`にある`records.txt`・`master.txt`・`expected.txt`をWindowsへコピーする。この3つは機密情報を含まないと明記されたテスト専用資料。

1. 「旧データ移行」タブの「旧PCデータを取り込む」で`records.txt`を選び、プレビューが67サービスであることを確認して取り込む。
2. 先頭のサービス`1`を選び、`master.txt`のテスト専用マスターを手入力する。
3. 生成して貼り付けた文字列が、`expected.txt`の1行目と完全一致することを確認する。他のサービスも、番号と同じ行の期待値で比較できる。

本番用の旧`data.txt`は、この動作確認には使用しない。

## 通常起動・更新と確認結果の連絡

通常起動は`New Password Manager.exe`のダブルクリック、または引数なしの起動。通常の設定保存先は**EXEと同じフォルダの`data.json`**で、テスト用の保存先とは別になる。作業フォルダやショートカットの開始場所に左右されない。書込みできない場所では保存に失敗するため、ユーザーが書込みできるフォルダへ展開する。

更新時はアプリを終了し、現在のフォルダの`data.json`と必要なバックアップを別途コピーして保管する。新しいZIPを別フォルダへすべて展開し、使用する`data.json`を新しいEXEの隣へコピーしてから起動する。EXEだけを差し替えない。コピー先にデータがある場合は上書きせず、両方を保管して使用する正本を選ぶ。

以前の版の通常データを引き継ぐ場合は、アプリを終了して`%APPDATA%\new-password-manager\data.json`をバックアップし、新しいEXEと同じ場所へコピーする。テスト用データは対応する`%TEMP%\new-password-manager-tests\<プロファイル名>`から取得する。新アプリはこれらの旧保存先を自動で探索・移動しない。

問題があれば、起動コマンドのプロファイル名、操作順、表示されたエラー、Windowsでの表示倍率を記録して連絡する。実マスター・実生成パスワード・本番ファイルは添付しない。

より詳しい失敗時・表示倍率・スリープ・ファイル操作の確認項目は[デスクトップの操作・検証手順](desktop-validation.md)を参照する。
