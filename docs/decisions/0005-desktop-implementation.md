# ADR 0005: デスクトップ初回実装の保存・登録条件

- 日付：2026-10-27
- 状態：一部を[ADR 0007](0007-portable-desktop.md)で変更（EXE隣への保存、復元・エクスポート・保存場所表示の削除）。その他は採用。保存方式と新規登録条件は本日のユーザー回答による。Windowsでの実動作確認は未実施。

## 決定

保存はまず平文のUTF-8 JSONとし、`formatVersion: 1`、生成方式はレコード単位の`legacy-pc-v1`で識別する。暗号化、OS鍵ストア、外部DB、追加ライブラリは初回に導入しない。マスターと生成結果は保存しない。

Windowsの保存領域はElectronの`appData`直下の固定名`new-password-manager`、正本は`data.json`。通常は`%APPDATA%\new-password-manager\data.json`となり、「保存場所」で実際のパスを確認できる。アプリの表示名・展開先・カレントディレクトリを保存先に使わない。単一起動に制限する。

新規登録は8〜64文字。名前は前後空白を取り除き、空白のみ・改行・制御文字を拒否する。大小文字・Unicodeを正規化せず、処理後の名前の完全一致で重複を拒否する。記号は旧登録UIの受付範囲（ASCII記号・空白・円記号U+00A5）を維持し、入力の初出順で重複除去した文字列を保存する。旧ファイルの既存長さ・名前・記号はこの新規ルールで再登録しない。

## 保存と復元

mainで保存要求を直列化し、各変更を最新の確定状態に適用する。候補全体の検証、既存正本のバイト一致確認、直前正常版`data.json.bak`の作成、同じディレクトリのランダム名一時ファイルへ書込み・sync・close、rename、メモリ確定の順とする。新規ファイルは排他的に作成する。起動時は一時ファイルを自動昇格しない。

不存在だけを初回起動とする。破損・読込失敗は空データにせず、登録・履歴追加・通常保存を禁止する。復元は検証済みJSONの件数・履歴件数を確認してから全件置換する。破損正本からの明示的な復元では、破損原文を`data.json.rejected-<UUID>`に残し、正常バックアップを破損データで上書きしない。未知の形式・生成方式は復元による書換えも拒否する。

旧PCファイルは0件の保存先にだけ取り込む。解析成功後にプレビューし、mainに保持した内容をtokenで確定する。元バイト列を`legacy-import-<UUID>.txt`へ保管してから新正本を作り、元ファイルは書き換えない。途中失敗ではバックアップだけ残る場合があるが、完了とは通知しない。バックアップの自動削除はしない。

書き出しはアプリ保存領域の外へ、新しいファイル名で平文JSONを作る。既存ファイルを上書きしない。

## 画面・IPC・コピー

旧2タブを維持し、補助操作は上部の小さなファイル操作ボタンへ置く。履歴チェック解除時は最新へ戻し、サービス・タブ切替時はマスターを消す。マスターは生成送信直後にフォームから消し、失敗時も再入力する。登録成功後はフォームを初期化し、先頭サービスを選ぶ。登録タブは維持する。salt追加には確認を挟む。

main/preload/rendererの分離、sandbox・contextIsolation・CSP、送信元ウィンドウ・メインフレーム・完全URLの検証を維持する。公開APIは固定の操作のみ。salt値・生成結果をrendererへ返さない。汎用IPCや任意ファイルパスを受け付けない。プレビュー後にデータが変更された場合はtokenを拒否する。

クリップボードはmainの直列キューで管理する。コピー成功完了から30秒後、スリープ復帰、通常終了時に、直近のコピーと一致する場合だけ消去する。失敗した再コピーは既存期限を取り消さない。消去失敗は成功表示にせず、期限後の再確認で再試行する。比較直後の他アプリの書込み、同一文字列の再コピー、OS履歴、強制終了時の消去は保証できない。

過大入力への防御として、ファイル取込は10MiB、生成用マスターと新規の名前・記号は1024文字、説明は100000文字を上限にした。これらは旧仕様の下限や既存条件の丸めではなく、処理境界の上限。既存ファイルにこれを超える値が必要な場合は別途確認する。

## 選択理由・代替案・残る確認

小規模な設定とsalt履歴に対して、ユーザー承認の平文JSONで先にローカル保存・バックアップ・移行を整える。暗号化を最初に必須とする案は、解除方法・鍵の復元・Androidへの転送まで決める必要があり、今回は採用しない。保存の暗号化と生成アルゴリズムの変更は独立した判断とする。

PC互換コアは提供67件および旧ソース由来の固定ベクトルで検証する。旧Androidには剰余精度と乱数境界の差異があり、[調査メモ](../legacy-mobile-differences.md)に記録した。その後のユーザー承認により、新Androidも剰余・乱数ともPC互換へ統一すると[ADR 0006](0006-shared-pc-generator.md)で決定した。Androidの生成機能の接続は未実施。

同日の追加確認：ユーザーの申告では既存の本番データの生成長はすべて10文字以上。剰余精度の差異については移行しやすい側を選ぶよう依頼を受け、実装・検証済みのPC版の正確な整数計算を採用した。実データの読込はしていない。この時点では乱数境界の差異を決定に含めなかったが、追加説明後にユーザーから同様に移行の容易さを優先する承認を得た。乱数もPC互換を採用する最終判断はADR 0006に記録する。

Windowsのrename・ロック・空き容量・クリップボード・スリープ・DPI・通常終了の実動作確認は残る。WSLの失敗注入テストを実機試験と混同しない。ディレクトリのflushや停電時の完全な耐久性、バックアップ世代の自動管理、Android実機の動作は今回保証していない。
