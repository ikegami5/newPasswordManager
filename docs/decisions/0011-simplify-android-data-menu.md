# 0011: Androidのデータ操作を取り込みへ集約する

日付：2026-10-28。状態：採用・実装済み。ADR 0010の画面操作・実機向け互換性チェックを一部変更する。

## 理由

ユーザー指定により、アプリ内の互換性チェック、直前版を確認して復元、再読込を削除する。PC側の元JSONを保持する運用なので、戻したい場合や読み直したい場合もファイルの再取り込みで対応する。互換性は既存のローカル固定テストで確認する。

## 変更

- データメニューはファイル取り込み／再取り込みのみ。確認後の全件置換、元ファイル不変、10MiB上限、空ファイル拒否を維持する。
- 手動復元用API・プレビュー種別・バックアップ有無の画面用状態を削除する。起動時の内部読込は残し、手動の再読込APIとは分ける。
- 保存の途中失敗から現行データを守る2スロットは維持する。保存形式は変えない。読込エラー時にはファイル取り込みを案内する。正常な残存スロットを保護し、検証・確認済みのJSONから復旧する。未知の保存・モデル・生成版への上書き禁止は継続する。
- 初期キャッシュ掃除に失敗しても取り込み操作を使えるようにし、次の取り込み開始時に掃除を再試行する。失敗を空データへ自動置換しない。
- 固定67＋92件の検証ヘルパーをテスト専用ファイルへ移す。期待値・原本は変更せず、ローカルテストを維持する。アプリのエントリーから検証コード・fixtureを参照しない。

## 詳細欄のスクロール

複数行のサービス詳細で最終行が見切れる報告に対し、ScrollView本体のpaddingを`contentContainerStyle`へ移す。下端の余白を内容のサイズに含める。サービスを変更したら詳細欄のスクロール位置も先頭へ戻す。外側のスクロールと詳細欄のスクロールは維持する。

[React Native公式のcontentContainerStyle](https://reactnative.dev/docs/scrollview#contentcontainerstyle)は、子要素を包む内容側のコンテナへ適用する指定。修正後の最終行表示は実機で再確認が必要。

## 検証と影響

再取り込みによる旧JSONへの切替、破損後の確認付き再取り込み、残存正常スロットの保護、未知版の上書き拒否をローカルで検証する。互換生成・クリップボード・マスター入力条件は変更しない。

React／TypeScript側の変更で、依存・ネイティブ設定・OSバックアップ方針は変えない。development clientではMetroから再読込して確認でき、APKの再インストールは不要。操作と実機の未確認項目は[Androidの手順書](../android-validation.md)へ記録する。

実施結果：`npm run check`成功（Vitest 252件＋Node 4件、型チェック・lint・書式）、`npm run bundle:android`成功。詳細欄の修正後の実機表示は未確認。
