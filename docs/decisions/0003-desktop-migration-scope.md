# ADR 0003：デスクトップを先に、旧UIを基準として移行する

- 日付：2026-10-27
- 状態：採用（移行範囲とUIの基本方針）。詳細設計は提案段階。

## 背景

ユーザーから、デスクトップアプリ側から設計し、既存の仕様・UIをほぼそのまま移行する指定があった。また、新PC版のデータを旧Androidアプリで読み込む必要はなく、新Android版への移行後に使えればよいと確認した。

## 決定

- 旧PC版の「パスワード生成」「サービス登録」の2タブ、フォーム配置、初期値、操作順を設計の基準にする。
- 生成結果を表示せずコピーする動作、salt追加による変更と過去履歴の再生成、既存の生成結果を維持する。
- デスクトップの互換生成・保存・UI・WindowsのOS連携を先に具体化し、共通コアとデータモデルを後の新Android版にも使える構成にする。
- 旧形式の取り込みを設計する。新PC版から旧Android形式への書き出しは要件にしない。
- 保存失敗時のデータ喪失や、他アプリのコピー内容の消去など、旧実装の問題は移行時の変更案として明示する。

## 理由と影響

既存利用者の操作を保ち、UIの刷新による仕様の取りこぼしを抑える。旧Androidとの往復互換を必要としないため、新保存形式を独自エスケープへ制約せず設計できる。

保存形式・暗号化、条件別の最小文字数、新規登録の記号順、確認ダイアログなどは、このADRだけで採用済みにしない。[詳細設計](../desktop-design.md)に旧挙動と提案を分けて記録し、実装前に確定する。

## 比較した案

- UI全体の刷新：ユーザーの移行方針に合わせ、初回範囲に含めない。
- 旧Android形式への書き出し維持：ユーザー確認により不要。
- 旧実装の失敗時動作までそのまま移植：データ保護の作業規約と両立しないため、問題点を記録して改善案を示す。
