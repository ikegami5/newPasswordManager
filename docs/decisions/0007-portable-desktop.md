# ADR 0007: EXEと同じ場所への保存とデスクトップ操作の簡略化

- 日付：2026-10-27
- 状態：採用。ユーザーの変更依頼による。保存・画面変更は実装済み。ウィンドウアイコンも組み込み済み。Windows実表示は未確認。アイコンの原本とEXEへの埋め込みは後続の[ADR 0008](0008-desktop-icons-and-spacing.md)で更新した。

## 決定と理由

通常起動では`app.getPath('exe')`の親ディレクトリを保存先とし、`New Password Manager.exe`の隣へ`data.json`を保存する。カレントディレクトリやショートカットの「作業フォルダー」には依存しない。開発起動はElectron本体のインストール先を汚さず、`app.getAppPath()`の直下へ保存する。テスト用プロファイルは従来どおり一時領域へ分離する。

アプリを置いたフォルダごと管理するというユーザーの希望を優先し、ADR 0005のAppData保存方針を変更する。書込み可能な場所へ展開して使い、書込み拒否時は別の場所へ勝手に保存せずエラーを表示する。Chromiumのセッション用ファイルは保存先の`session/`へ置く。

バックアップ復元・エクスポート・保存場所表示は画面、preload、IPC、mainサービスから削除する。旧PC形式の初回取り込み、登録、生成、salt履歴追加は維持する。保存途中の失敗に備える内部の直前正常版`data.json.bak`と旧ファイル原文バックアップは維持する。アプリからの復元・JSON書き出し機能は設けない。

文字サイズを16pxから14px、line-heightを1.3とし、余白・ボタン・説明欄を小さくする。ウィンドウ初期寸法900×620は維持し、狭い画面や拡大表示ではスクロールを許容して操作要素を隠さない。

## アイコン

ユーザー添付の`file.svg`は確認済み。WSLに既存のSVG変換ツールが見つからず、`@resvg/resvg-js`の開発依存追加を提案したところ、ユーザーは追加せずPNGまたはICOを用意する方針を選択した。追加依存は導入していない。その後、ユーザーが提供した`key.ico`を確認したところ実体は512×512のBMPだったため、既存のExpo依存`jimp-compact`で画像を読み、16/24/32/48/64/128/256pxのPNGフレームを含む標準ICOに変換した。元バイト列は`icon-source.bmp`として保管し、配布用`icon.ico`を`extraResources`で同梱して`BrowserWindow.icon`に指定する。追加依存は導入していない。通常ビルド時の再変換は不要。Windows実表示は未確認。

## 既存データと更新

旧AppData保存先とテスト用保存先を自動探索・読込・移動しない。前の版で作った`data.json`を引き継ぐ場合は、アプリを終了し、元ファイルをバックアップしたうえでEXEと同じフォルダへコピーする。コピー先に既存データがあれば上書きせず、両方を保管してから使用する正本を選ぶ。

ZIPを新しいフォルダへ展開した場合は、実行ファイルと一緒にデータも引き継ぐ必要がある。アプリやZIPを共有するときに、隣の設定・履歴・バックアップを一緒に含めないようにする。PCから新Androidへ渡すファイルも、PC停止中にコピーした`data.json`を使う方針とし、Androidの取込・保存・OS連携の実装は別途行う。

## 検証

保存先のテストで、パッケージ版はEXEの親、開発版はアプリルート、テスト用は一時領域となることを確認した。復元・エクスポート・保存場所表示のAPIと対応する不要コードを削除した。型チェック・lint・229テスト成功。書式確認とWindows用ZIPの再作成も行う。Windows実画面の見た目・ファイル書込みは未確認。
