# ADR 0001：シンプルな構成とローカル検証

- 日付：2026-10-22
- 状態：採用（基本方針）。開発環境の導入方式と固定バージョンは[ADR 0002](0002-development-environment.md)で具体化した。機能実装は未着手。

## 背景

旧PC・スマホアプリを単一リポジトリに統合し、生成結果の互換性を保ちながら保守しやすい構成へ移行する。ユーザーから、シンプルな構成とし、GitHub Actionsを使用せず、デスクトップは当面Windows上で検証できればよいとの指定があった。

## 決定

- npm workspacesを使い、Electron＋React＋TypeScriptのPCアプリ、React Native＋TypeScriptのAndroidアプリ、生成・解析・データモデルの共通コアを基本構成とする。
- PC開発・配布はelectron-vite＋electron-builderを基本とし、具体的なバージョンと環境は導入前に確認する。
- 初期は追加のモノレポ管理ツールやCIサービスを導入しない。GitHub Actionsのワークフローは作成・実行しない。
- 型チェック・lint・互換性テスト・ビルドをローカルで実行し、再実行可能な手順と結果を記録する。
- 開発と共通ロジックの検証はWSL（Ubuntu）で行い、デスクトップアプリの動作は当面Windows上で確認する。macOS・Linux上でのアプリ検証は当面要求しない。
- Windowsデスクトップ検証のために必要な範囲ではWindowsホストを利用する。追加インストール・環境設定変更は事前確認する。
- Androidのローカルビルドと端末での検証を行う。iPhone対応は対象外。

## 理由と影響

共通コアにより生成仕様の重複を抑え、既存npmとローカルコマンドを中心に保守する。PR等を契機としたGitHub Actionsでの自動検証は行わないため、変更時のローカル実行と結果の記録を作業規約に含める。

Windowsでの動作確認とWSL上のロジック検証は別々に記録する。Windowsのビルド作成・受け渡し方法、配布・署名、Androidの導入方式、保存・転送・暗号化等は詳細選定で決める。

## 比較・保留した案

- GitHub Actions：ユーザー指定により使用しない。
- 初期からのmacOS・Linuxアプリ検証：当面の対象に含めない。
- Kotlin＋Jetpack Compose：AndroidのOS連携を優先する必要が生じた場合の代替案として記録する。

技術の比較と未決定事項は[技術方針](../technology-proposal.md)、調査した旧仕様は[旧プロジェクト調査](../legacy-projects.md)を参照する。
