# 0010: Androidの取り込み・保存・生成を実装する

日付：2026-10-27。状態：採用・実装済み。端末上の受入確認は未実施。

2026-10-28追記：[ADR 0011](0011-simplify-android-data-menu.md)でアプリ内互換性チェック・手動復元・再読込を削除した。以下は初回実装時の決定として残す。内部の保存保護は維持する。

## 決定

ユーザー承認により、SDK 58対応のClipboard・DocumentPicker・FileSystem・Crypto・Picker・Safe Areaを導入する。初回範囲は[ADR 0004](0004-android-migration-scope.md)の選択・生成・コピーと、設定の取り込み・再取り込み・直前版復元。サービスの登録・編集・履歴追加はPC側で行う。デスクトップの画面・保存先は変更しない。

生成は[ADR 0006](0006-shared-pc-generator.md)の`legacy-pc-v1`に統一する。SHA-512はTextEncoderでUTF-8バイト列を明示してExpo Cryptoのバイナリdigest APIから注入し、マスターはtrim・正規化・文字種制限をしない。ユーザー指定により空文字も受け付ける。上限は1024 UTF-16コード単位。入力欄は送信・サービスや履歴の変更・背景化・フォーカス喪失時に消去する。

## ファイルと保存

PCアプリ停止中にEXE隣の`data.json`をコピーし、端末へ転送してシステムのファイル選択から取り込む。旧PC形式のUTF-8テキストも初回移行用に受け付ける。10MiB以下、全件の構造・形式版・生成版を検証し、0件・解析失敗・未知版は拒否する。新規登録の長さ制限や記号重複除去を既存データへ適用しない。

確認画面にはサービス・履歴の件数、追加・削除・変更、欠落する既存履歴の件数を表示する。全件置換を明示し、確認後に固定した候補を保存する。元URIを再読込せず、元ファイルは変更しない。旧テキストの再移行ではIDを再採番するため、継続利用では同じPCデータ由来のJSONを推奨する。

正本は`Paths.document/newpm/`の平文JSON。内部エンベロープは`storageVersion: 1`、単調増加する`sequence`、文書のSHA-256、共通`DataDocument`を含む。SHA-256は偶発的な破損の検出用で、暗号化や改ざんへの認証ではない。マスター・生成結果は保存しない。

`snapshot-0.json`と`snapshot-1.json`の2スロットを交互に使う。現行の正常スロットを残して別スロットへ書き、読戻しのバイト一致・モデル・ダイジェスト検証後にメモリ上の現行を切り替える。正常な直前版を1世代保持する。Expoの非同期`File.write`完了を待つが、fsyncや移動の原子性を仮定しない。物理的な電源断での永続化までは保証しない。

読込時は両スロットを検証し、正常なら大きい世代を採用する。破損や読込エラーを空データ・古いデータへ黙って置換せず、読込エラーにする。残る正常版の復元またはファイル再取り込みはプレビュー後の明示操作とする。未知の保存・モデル・生成版がある場合は上書きを禁止する。保存失敗時は現行を保持するが、書きかけた非現行スロットの旧バックアップは失われ得る。書きかけの削除にも失敗した場合は生成を止めて再読込を要求する。

ファイル選択のコピーは専用キャッシュ内だけで読み、正常・失敗時とも削除する。確認待ちの候補はメモリに保持する。異常終了後のキャッシュは起動・再読込時に掃除する。DocumentPickerが選択時に行うコピー自体はサイズ検査より前なので、巨大ファイルは一時的にキャッシュ容量を消費し得る。FileSystem等が宣言するREAD／WRITE_EXTERNAL_STORAGEは`blockedPermissions`で除外し、広域ストレージ権限を要求しない。

## OSバックアップ

`app.json`とローカルconfig pluginを正本とし、生成済みネイティブファイルを手編集しない。`allowBackup=false`に加え、Android 11以前の`full-backup-content`と12以降の`data-extraction-rules`で`file/newpm/`を除外する。後者はcloud-backup・device-transferの両方を指定する。取り込みキャッシュはOSが自動バックアップ対象外とするcache領域。メーカー独自の移行処理まで保証するものではなく、標準設定の適用と実機動作は区別する。

[Android公式資料](https://developer.android.com/identity/data/autobackup)は`allowBackup=false`だけでは一部メーカーの端末移行を無効化できない場合があると説明する。保存先が`getFilesDir()`配下であることは導入済みExpo FileSystemのAndroidソースでも確認した。

## 生成・クリップボード

サービス層で生成を直列化し、処理世代と前景・フォーカスをコピー直前に検査する。離脱後に古い生成結果を新しくコピーしない。ネイティブへのコピー開始後に離脱した場合は、完了したコピーの所有情報を保持する。

`expo-clipboard`の`android.isSensitive=true`を使う。型と導入版Kotlin実装を確認した。コピー完了から30秒を計り、前景・フォーカスがある時だけ読み取り比較して消去する。時計の後退に備えて単調時計と壁時計の経過時間の大きい方を使う。背景中は読み取らず、期限後に戻ると消去を試みる。失敗時は約5秒間隔で再試行する。手動消去も自身が最後にコピーした内容と一致する場合だけ行う。比較後から書込みまでの他アプリ・OSとの競合を原子的に防ぐAPIではない。

直近結果は比較に必要な一時メモリにだけ保持し、消去・別内容検出後に参照を捨てる。JavaScript文字列の物理的な完全消去、強制終了後の消去、OSやキーボード履歴の消去は保証しない。通知には生成結果を含めない。

## 検証と配布

UTF-8エンコードと不正UTF-8の拒否にはTextEncoder／TextDecoderを使う。[SDK 58の公式資料](https://docs.expo.dev/versions/v58.0.0/sdk/expo/#encoding-apis)でReact Native 0.88のHermesに両APIがあることを確認した。ネイティブへの文字列変換にエンコード方針を委ねず、PCと同じUTF-8バイト列をハッシュへ渡す。

純粋な保存・サービス・クリップボードはVitestで失敗・競合・版保護を検証する。「データ→互換性チェック」は機密情報なしの固定67＋92件だけを使い、Expo Cryptoと共通コアを実際のAndroidランタイムで照合する。Nodeテストでは同じ159件の一致と元GUI資料との一致を検証するが、それをHermes実行済みとは扱わない。

ローカルdebug APKはExpo development client。Metroとの接続が必要。正式配布の署名・鍵保管・更新・単体起動APKは未決定。環境・固定依存・操作・実機の未確認項目は[Androidの動作確認](../android-validation.md)とREADMEに記録する。
