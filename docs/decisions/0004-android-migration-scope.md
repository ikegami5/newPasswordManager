# ADR 0004：Androidは旧版の選択・生成・コピーの範囲で移行する

- 日付：2026-10-27
- 状態：採用（初回の機能範囲）。OS連携・保存等の詳細は設計案。

## 背景

デスクトップ設計に続いてAndroid設計を行う依頼があり、ユーザーへ登録・変更機能の要否を確認した。初回は旧版と同じ「PCから取り込み、選択・生成・コピーする」範囲でよいと回答を得た。

## 決定

- サービス選択、説明、履歴選択、マスター入力、生成、通知、手動消去の1画面を基準に移行する。
- サービス登録・編集・削除・salt追加はPC側で行い、Androidには取り込んだスナップショットを持たせる。
- PCと共通のデータモデル・生成版の識別を使う。旧形式の生成版を根拠なく決めず、不一致は記録・確認する。
- 取り込み・再取り込みと失敗からの回復を設計し、読込失敗を空データとして保存しない。
- 新Androidでの自動入力・生体認証・クラウド同期は初回範囲に含めない。

## 理由と影響

旧版の利用方法を保ち、端末間の編集競合を初期から導入せず移行できる。PC側の更新は明示的な再取り込みで反映する。

バックグラウンドや強制終了時のクリップボード消去にはOS上の制約があるため、旧タイマーの移植だけで保証しない。前景・復帰・手動消去を分けた案を[Android移行設計](../android-design.md)へ記録した。コピーの細部、保存暗号化、転送方法、入力制限、追加依存・設定はこのADRだけで採用・導入済みとしない。

## 比較した案

- Androidでも登録・salt追加を行う：ユーザー確認により初回範囲に含めない。
- 旧アプリの保存領域を直接読む：新パッケージとの分離とOS制限を踏まえ、明示的な取り込みを設計する。
- 常駐処理で30秒消去を保証する：フォーカス制限等もあるため初期案にしない。保証が必須なら方式を再検討する。
