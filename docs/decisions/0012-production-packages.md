# 0012: 旧PC移行を専用タブへ移し、正式配布物を作成する

日付：2026-10-28。状態：採用・ビルド済み。

## 確認済みの運用

ユーザーからPC・Androidの動作確認、本番用JSONへの移行が完了したと報告があった。実データをエージェントが読んだり取り込み直したりする必要はない。この報告は、今回変更するタブ配置や新しい正式APKの実機確認とは区別する。

## PC版

従来の「パスワード生成」「サービス登録」に「旧データ移行」タブを追加し、上部共通の取り込みボタンと取り込みプレビューを移す。登録0件のときだけ旧PCテキストを取り込める制限はmain側・画面側とも維持する。JSON移行済みの通常利用では旧移行は不要。タブ切替でマスター入力と未確定プレビューを消去する。

Windows x64向けのZIPを従来と同じ構成で配布する。インストーラーやWindowsコード署名は追加しない。EXE隣のJSON保存、アイコン、日本語・英語の同梱は維持する。配布物はアプリコードだけを含み、本番用JSONを同梱しない。

## Android版

Metroなしで起動できる`assembleRelease`の署名付きAPKをローカルで作成する。EAS・Play Store・外部への公開やアップロードは行わない。

ユーザー承認により正式版用のRSA 3072ビット鍵を新規作成し、`.local-tools/android-signing/`へ鍵と認証情報を保存する。Git対象外、ディレクトリ700・ファイル600。鍵やパスワードの本文は表示しない。更新時は同じ鍵を使い、フォルダ全体を利用者が私的にバックアップする。作成スクリプトは既存の鍵・認証情報を上書きしない。

生成ネイティブコードを手編集しない。ローカルconfig pluginから`apps/android/gradle/release-signing.gradle`を適用し、正式署名を読み込む。認証情報は私的なpropertiesファイルから読み、パスワードをGradleのコマンド引数へ展開しない。署名情報がない場合はreleaseビルドを拒否し、公開されたdebug鍵にフォールバックしない。

アプリIDはユーザー指定により開発版と同じ`io.github.ikegami5.newpasswordmanager`。署名が異なるため、初回切替では開発版のアンインストールとJSONの再取り込みが必要。内部データが消えることを手順に明記し、元JSONの確保後に利用者が操作する。エージェントは端末データの読込・アンインストールを実行しない。正式版同士の更新は同じ鍵とIDを保ち、versionCodeを増やして上書きする。

## ビルド環境

承認済みのKotlin同一プロセス方式をreleaseビルドへ使用する。初回releaseビルドで`OutOfMemoryError: Metaspace`（上限512MiB）が発生した。ユーザー承認により、本番ビルドコマンドだけMetaspaceを2GiB、heapを2GiB、Gradleの並列数を2とする。global設定・追加ツール・依存更新は行わない。ビルド用コマンドと、失敗時にSDKの自動導入を行わず停止する事前チェックをプロジェクトのスクリプトへ残す。

## 検証・手順

既存の固定互換性・保存・IPC等のローカルテストを継続する。Windows ZIPに本番データ・署名情報がないこと、言語・アイコン・アプリバンドルを検証する。Androidは正式鍵との証明書一致、署名、debuggable無効、バンドル同梱、バックアップ除外、不要ストレージ権限なしを確認する。新しい配布物の実機起動結果は別に記録する。

- [Android正式版のインストール・更新と署名鍵の保管](../android-installation.md)
