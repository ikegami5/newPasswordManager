## WSLでビルドする

JDK・SDKの導入手順は[README](../README.md#jdk-17とandroid-sdkの導入ユーザー作業)を参照してください。既存Java 11の既定値は変えません。依存はlockfileに固定しています。

```bash
source scripts/env.sh
npm ci
npm run check
npm run bundle:android
npm run build:android:debug
```

APKは`apps/android/android/app/build/outputs/apk/debug/app-debug.apk`へ生成します。最低OSはAPI 24（Android 7.0）、ビルド設定はcompileSdk 37／targetSdk 36です。実機の対応確認は別に行います。

今回の環境では、通常ビルドが一度成功した後の再ビルドでKotlinコンパイルの進捗が止まり、Gradleの`--no-daemon`だけでも同じ箇所から進みませんでした。ユーザー承認により、次の一時オプションで最終APKのビルドに成功しました（1分20秒）。これは[公式のKotlinコンパイル実行方式](https://kotlinlang.org/docs/compiler-execution-strategy.html)の指定で、追加インストール・`gradle.properties`・global設定の変更は行いません。

```bash
source scripts/env.sh
npm run prebuild:android
apps/android/android/gradlew -p apps/android/android assembleDebug --console=plain --no-daemon -Pkotlin.compiler.execution.strategy=in-process
```

`--no-daemon`はGradle側、`kotlin.compiler.execution.strategy`はKotlin側の別の指定です。再現時には上記を使い、原因がKotlinデーモンだけにあると断定しないでください。

## ワイヤレスデバッグでインストールする

Android 11以降の端末とPCを同じWi-Fiネットワークへ接続します。以下は2026-10-28にユーザーが接続・インストールまで完了した経路です。各ターミナルのコマンドは、このリポジトリのルートで実行してください。IP・ポートは毎回端末の表示を確認し、実際の値は手順書へ保存しません。

### 1. WSLのターミナルAでADBサーバーを起動する

今回の環境では、通常のADB起動でペアコード入力後や`adb devices`が応答しませんでした。次の前景起動を使うとペア設定へ進めました。停止の根本原因は未特定です。このターミナルは接続中、開いたままにします。

```bash
source scripts/env.sh
adb nodaemon server
```

### 2. Androidのペア設定画面を開く

「設定 → 開発者向けオプション → ワイヤレスデバッグ」を有効にし、「ペア設定コードによるデバイスのペア設定」を開きます。その画面を開いたまま、表示されたIPアドレスとペア設定用ポートを次で入力します。

### 3. WSLのターミナルBでペア設定する

```bash
source scripts/env.sh
read -r -p 'AndroidのIPアドレス: ' newpm_android_ip
read -r -p 'ペア設定画面のポート: ' newpm_pair_port
adb pair "${newpm_android_ip}:${newpm_pair_port}"
```

`Enter pairing code:`が表示されたら、端末上のコードを入力します。コードをコマンド引数・文書・チャットへ残す必要はありません。ペア設定コマンドの成功を確認してから次へ進みます。

### 4. 接続用ポートでADB接続を確立する

Androidのワイヤレスデバッグのトップ画面に戻り、「IPアドレスとポート」を確認します。**ここの接続用ポートは、ペア設定コード画面のポートとは別です。** ペア設定だけでは`adb devices`に端末が出ない場合があるため、同じターミナルBで明示的に接続します。

```bash
read -r -p 'トップ画面の接続用ポート: ' newpm_connect_port
adb connect "${newpm_android_ip}:${newpm_connect_port}"
adb devices
```

`connected to ...`と表示され、`adb devices`で対象端末が`device`となれば接続完了です。IPも変わっている場合は`newpm_android_ip`を再入力してください。複数端末が接続されている場合は、以下の各ADBコマンドで`adb -s "${newpm_android_ip}:${newpm_connect_port}" ...`と対象を明示します。

### 5. APKをインストールする

```bash
adb install -r apps/android/android/app/build/outputs/apk/debug/app-debug.apk
```

`Success`を確認します。作成済みAPKがあれば、インストールのための再ビルドは不要です。

### 6. Metroを起動してアプリを開く

以下はインストール後の起動手順です。今回のユーザー報告はインストールまでで、この手順の実機での成功報告はまだありません。

```bash
adb reverse tcp:8081 tcp:8081
npm run start --workspace @newpm/android -- --localhost
```

Metroのターミナルも開いたままにします。端末でNew Password Managerを開き、development clientの接続先に`http://127.0.0.1:8081`を指定します。ワイヤレスでもADBのreverse転送を使うため、このアドレスです。Expo Goは使いません。

画面が開いたら、下記の架空JSONを取り込んで表示・履歴選択・生成を確認します。アプリ内の互換性チェック機能は削除しました。固定期待値との照合はWSLで`npm test`を実行します。

### 再接続・終了

- ペア設定が残っていれば、次回は通常`adb pair`を省略し、サーバー起動 → 現在の接続用ポートで`adb connect` → `adb devices`と進めます。
- ワイヤレスデバッグの再有効化等でIP・ポートが変わることがあります。ターミナルを開き直した場合も、上記のIP・接続用ポートを再入力してください。
- ADBが切断された場合は、接続を戻した後に`adb reverse tcp:8081 tcp:8081`も再実行します。インストール済みアプリの再インストールは通常不要です。
- 検証終了時はMetroをCtrl+Cで終了し、ターミナルAのADBサーバーもCtrl+Cで終了できます。ADBサーバーの終了は、そのサーバーを使う他のデバッグ接続も切断します。

## データメニューの各操作の仕様

### ファイルを取り込み／ファイルを再取り込み

どちらも同じ取り込み処理です。PCアプリを終了してコピーした`data.json`を選び、検証と件数プレビュー後に確認すると、Android内部のサービス・生成条件・salt履歴を全件置き換えます。既存サービスへの追加や差分マージはしません。再取り込みという表示は、既にデータがある場合の呼び分けです。

元のPCファイルは変更しません。Androidは取り込み後のコピーを内部に保存し、PC側の変更を自動追跡しません。PCで更新したら新しいJSONを転送して再取り込みします。キャンセル・形式不正等では現在のデータを置き換えません。0件のファイルも拒否します。初回移行用に旧PCテキスト形式も受け付けますが、継続運用はPCのJSONを使います。

### 以前のデータを使いたい場合・読込エラーの場合

戻したいPCのJSONを「ファイルを再取り込み」から選び、確認して全件置換します。アプリ内の直前版復元・手動の再読込はありません。元JSONをPC側で保持する運用です。

起動時はAndroid内部の保存データを自動で読みます。読込エラーも空データと区別して通知し、PCのJSONの再取り込みを案内します。未知の保存・生成・モデル版が見つかった場合は、誤上書きを避けるため取り込みによる置換も禁止します。対応するアプリで確認してください。

保存の途中失敗から現行データを守る内部2スロットは残しますが、画面からバックアップを選んで復元する機能はありません。キャッシュの掃除に失敗した場合は、次の取り込み開始時に再試行します。

### ローカルでの互換性検証

`npm test`で提供67件・旧PC由来の合成92件の固定期待値と照合します。空マスター・Unicode・過去salt・記号順と重複・境界長・生成不能等を対象とし、生成不能の15件も想定したエラーとの一致を確認します。固定資料や検証コードはアプリへバンドルしません。資料の出典は[fixtureの説明](../packages/compatibility-fixtures/README.md)を参照してください。

## 画面の操作

1. PCアプリを終了し、EXEと同じディレクトリの`data.json`を別名コピーして端末へ転送します。PCの元ファイルは保持してください。
2. Androidで「ファイルを選ぶ」、または「データ→ファイルを取り込み」を押します。旧PC形式のUTF-8テキストも移行用に選択できます。
3. 件数を確認して「確認して取り込み」を押します。再取り込みは全件置換です。削除・変更や履歴の欠落件数を確認してから確定してください。0件のファイルでは置換できません。
4. サービスとパスワードの履歴を選び、PCと同じマスターを入力して「生成」を押します。空文字も受け付けます。前後空白・Unicode・記号を変更せず、1024文字まで扱います。
5. コピー成功の通知後、別アプリへ貼り付けます。結果自体はアプリ内には表示しません。マスター欄は消去します。
6. 前景ではコピー完了から約30秒後に、自分のコピーと同じ内容の場合だけ消去します。背景中には消去できず、戻った時に期限を確認します。すぐ消す場合は戻って「パスワード消去」を押します。他アプリがコピーした別内容は消しません。
7. PC側の変更はファイルを再転送し、「データ→ファイルを再取り込み」で反映します。以前のデータを使いたい場合も、保持しているJSONを再取り込みします。

データはアプリ内部の平文JSONです。クラウドバックアップと標準の端末移行から除外する設定を付けています。アンインストールや端末紛失からの復旧はPCの元ファイルを使います。生成結果・マスターは保存しません。強制終了後のクリップボード消去やキーボード等の履歴消去は保証しません。
