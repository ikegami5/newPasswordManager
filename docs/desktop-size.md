# デスクトップ配布サイズの調査・縮小結果

2026-10-27、アイコン差し替え・EXEアイコン埋め込み・項目間余白調整後のWindows x64 ZIPをWSLで測定。Electron 45.0.0 / electron-builder 26.15.3。サイズはMiB（1024×1024バイト）。以下の内訳は縮小前の基準値。ユーザー承認により日英限定を適用した結果を末尾へ記す。

## 内訳

| 対象                       |                            サイズ |
| -------------------------- | --------------------------------: |
| ZIP                        |                        146.21 MiB |
| 展開後の全体               |                        357.29 MiB |
| Electronを含むEXE          |                      約238.23 MiB |
| dxcompiler.dll             |                       約24.59 MiB |
| resources.pak              |                       約12.75 MiB |
| icudtl.dat                 |                       約10.32 MiB |
| Chromiumの言語ファイル55個 |                       約48.82 MiB |
| アプリ固有のapp.asar       | 約0.59 MiB（ZIP内では約0.11 MiB） |

アプリ固有のJS・CSS・main/preloadを含む領域は小さく、配布サイズの大半はElectronランタイム。元BMP・確認用PNG・画像生成スクリプト・開発依存は配布用ZIPへ同梱していない。

## 採用：言語を日本語・英語へ限定

electron-builderの`electronLanguages`で`ja`・`en-US`だけを同梱する設定。ユーザー向けの日本語UIは維持し、OS設定がそれ以外の言語の場合に備えて英語も残す。採用した設定は次のとおり。

```json
{ "electronLanguages": ["ja", "en-US"] }
```

現在のZIP内で該当53ファイルのサイズを合計すると、**ZIPで約11.04 MiB、展開後で約47.44 MiBの削減候補**となる。単純差分ではZIP約135.17 MiB、展開後約309.85 MiB。これらは既存アーカイブの圧縮サイズからの見積もりであり、設定後の再ビルド結果ではない。

実施時は`npm run check`とWindows ZIP再作成に加え、起動・ファイル選択・確認ダイアログ・生成/コピーなどが日本語・英語環境で動作するかを確認する。Chromiumの他言語の表示資源を省く変更であり、全言語対応を維持する案ではない。[electron-builder v26公式設定](https://www.electron.build/v26/docs/win/)

## その他の候補

| 案                           | 見込める効果と判断                                                                                             |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------- |
| ZIP圧縮をmaximumへ変更       | 展開後サイズは変わらない。公式は通常圧縮との差が小さく、ビルド時間が増えると記載している。実測比較は未実施     |
| アプリJS/CSSの圧縮強化       | app.asar全体が約0.59 MiBのため、大幅な削減にはならない。サイズ対策の優先度は低い                               |
| Electronランタイム自体の縮小 | 最大部分だが、現行の配布ランタイムを使う前提では簡単に減らせない。単なる設定変更の範囲を超えるため初手にしない |

圧縮設定の挙動は導入済みの型定義と[v26公式資料](https://www.electron.build/v26/docs/api/electron-builder.interface.platformspecificbuildoptions/)で確認した。現時点では、少ない変更で測定可能な削減が期待できる言語限定を採用した。Electronを採用する既存方針は変更しない。

## 測定方法

Python標準の`zipfile`でZIPの`file_size`・`compress_size`を集計し、展開先の各ファイルのサイズとも比較した。ZIPに対する言語ファイルの圧縮後サイズは、個別ファイルの`compress_size`を合計した値。アイコン差し替えに伴う小さなサイズ増減は最終ZIPの実測に含む。Windowsの実メモリ使用量や起動時間の測定ではない。

## 適用結果（2026-10-27）

ユーザー承認後、`electronLanguages: ["ja", "en-US"]`を設定して再ビルドした。[ADR 0009](decisions/0009-desktop-languages.md)を参照。

| 対象   |     縮小前 | 適用後（実測） | 削減量の目安 |
| ------ | ---------: | -------------: | -----------: |
| ZIP    | 146.21 MiB |     135.17 MiB |     約11 MiB |
| 展開後 | 357.29 MiB |     309.84 MiB |     約47 MiB |

ZIPは141735370バイト、展開後は324893201バイト。ZIP内と展開先の両方で、`locales/`に`ja.pak`と`en-US.pak`だけが残ることを確認した。アイコンの同梱一致も確認した。`npm run check`（Vitest 229件＋BMP変換4件）と`npm run package:windows`が成功。Windowsの日本語・英語環境での実動作確認は未実施。

## EXE自体のサイズについて

言語限定は全体を減らす変更であり、約238MiBのEXE自体は変わらない。公式ElectronのEXEとの比較、自己解凍型portableとWebView2方式の違い、EXEの隣に保存する要件への影響は[EXE本体の調査](desktop-exe-size.md)に記録した。現時点では配布方式・採用技術を変更していない。
