# デスクトップの操作・検証手順

更新日：2026-10-27。[ADR 0007](decisions/0007-portable-desktop.md)に合わせ、EXEと同じ場所への保存と操作の簡略化を反映。WindowsのGUI・OS操作はまだ未検証。

初めて動作確認する場合は[Windows版の導入・最初の動作確認](windows-installation.md)を参照。通常起動ではEXEの隣へ`data.json`を保存する。テスト用起動は従来どおり通常データと分離する。

## ビルドと隔離した起動

WSLで実行する。

```bash
source scripts/env.sh
npm run check
npm run package:windows
```

`apps/desktop/dist/New Password Manager-0.1.0-win.zip`をWindowsの書込み可能なフォルダへコピーし、すべて展開する。署名なしの検証用ZIP。Windows側で、EXEのある展開先をカレントディレクトリにしたPowerShellから起動する。

```powershell
& '.\New Password Manager.exe' --newpm-test-profile=desktop-validation-20261027
```

通常の保存先を読まず、Windowsの一時領域の`new-password-manager-tests\desktop-validation-20261027`を使う。タイトルに「テスト用」と表示する。同じ名前で再起動すると同じデータを読み、新しい名前なら空の保存先から確認できる。名前は英数字・ハイフン1〜64文字。

通常起動は引数なし。保存先はEXEの隣、開発起動はアプリルート。Chromiumのセッションは各保存先の`session/`へ置く。

## 操作と保存

- 2タブでサービス登録・生成・salt履歴の追加と選択を行う。新規登録は8〜64文字で、マスターは半角英数字8文字以上。マスターは送信直後に消し、生成結果を画面へ表示せずコピーする。
- 旧PC形式の取り込みはサービス0件の場合だけ利用できる。検証後に件数をプレビューし、確認してから確定する。選んだ元ファイルは変更せず、`legacy-import-<UUID>.txt`を保存先へ残す。エラーで部分取り込みしない。
- 通常保存は`data.json`、直前の正常版は`data.json.bak`。保存処理を直列化し、一時ファイルへの書込み・sync・close・rename後に状態を確定する。
- バックアップ復元・エクスポート・保存場所表示の画面とAPIは削除した。PCからAndroidへ受け渡すファイルは、PCアプリを終了してから`data.json`をコピーする。新Androidの取込機能は未実装。
- 読込失敗を空データにせず、登録・変更を禁止する。破損などで手動復旧する場合はアプリを終了し、破損原文とバックアップを保管してから正本を置き換える。未対応の保存版・生成版を無断で変換しない。

旧AppData保存先やテスト用領域のデータは自動移動しない。引き継ぎは[導入手順](windows-installation.md#通常起動更新と確認結果の連絡)を参照。実データは無断で読み込まない。

## Windowsの手動受入確認（未実施）

1. 初回0件、2タブの初期値、登録・生成の有効/無効、処理中の再送禁止を確認する。上部の補助操作が旧PC取り込みだけになっていることも確認する。配布物の`locales/`が`ja.pak`・`en-US.pak`だけとなり、日本語・英語のWindowsで起動・選択・確認ダイアログを利用できるかも確認する。
2. フォント14px・行間1.3・小さな入力間隔と、登録タブの大きな区切りの14px余白を900×620で確認する。生成タブはサービス選択・説明、変更・履歴、マスター入力の3グループ間に24pxの間隔があることを確認する。履歴欄・記号欄を表示し、DPI 100%/150%/200%とウィンドウ縮小でもスクロールして全操作へ到達できるか確認する。
3. 架空サービス登録→生成→メモ帳へ貼付→再生成で一致することを確認する。コピー成功から約30秒でアプリ所有の内容が消え、他アプリでコピーした別文字列は保持されることを確認する。
4. 再生成で期限が更新されること、生成失敗で先行コピーの期限が維持されること、スリープ復帰・通常終了時の消去と失敗通知を確認する。OS履歴・強制終了や比較直後の競合まで保証しない。
5. salt追加→以前の履歴で再生成→再起動で、履歴と生成結果が保たれることを確認する。サービス先の変更操作を行う機能ではない。
6. 未使用のテスト用プロファイルへ、テスト専用の`packages/compatibility-fixtures/pc/records.txt`を取り込む。67サービスを確認し、`master.txt`で生成した結果を`expected.txt`の対応行と完全一致で比較する。実データ・元fixtureは編集しない。
7. アプリ停止中にテスト用の`data.json`とバックアップを別途コピーしてから、テスト用正本だけを破損させる。再起動して空扱い・上書きされず、正常な`.bak`が維持されることを確認する。復旧は停止中の手動ファイル操作で行う。
8. 通常保存先の確認が必要な場合は、データのない専用の展開フォルダで架空データを登録し、EXEの隣へ`data.json`が作られるか確認する。書込み拒否・ファイルロック・空き容量の試験はテスト領域に限定し、環境設定を変更する場合は事前確認する。
9. 提供画像を変換したICOを組み込み済み。WindowsのタイトルバーとエクスプローラーのEXEに、青い円と白い鍵の透過アイコンが表示されることを確認する。配布フォルダの`resources/icon.ico`も確認する。実表示は未確認。

## 検証記録

2026-10-27の未コミット作業ツリー、WSL Ubuntu、Node 24.21.0 / npm 11.19.0。保存先変更・API削除後に型チェック・lint・229テスト成功。書式・ZIP再作成の結果はREADMEへ記す。共通ロジックの成功をWindows GUI・Android実機の証拠として扱わない。

Windowsの自動操作は、computer-useスキルの参照先guidance.mdの「Do not automate password manager apps or password manager websites.」により実施していない。アイコン変換用の追加ライブラリはユーザーが不要と回答したため、導入していない。
