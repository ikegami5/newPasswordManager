# Android版の移行設計

PC側の更新：[ADR 0007](decisions/0007-portable-desktop.md)により、PCのエクスポート機能は削除し、EXE隣の`data.json`をアプリ停止中にコピーしてAndroidへ渡す方針へ変更した。以下の「PCから書き出し」という提案は、このファイルコピーに読み替える。

2026-10-27更新：[ADR 0010](decisions/0010-android-implementation.md)に沿って初回機能を実装した。PC互換コア、Expo Crypto、平文JSONの内部2世代保存、10MiB以内の確認付き全件取り込み、前景と復帰時のコピー消去を採用した。ユーザー指定により空マスターも受け付ける。操作・依存・実機の未確認項目は[Androidの動作確認](android-validation.md)を参照。実機確認は未実施。

2026-10-28追記：ユーザー指定により、アプリ内の互換性チェック・手動復元・再読込を削除し、JSONの再取り込みへ集約した。内部保存保護・固定期待値のローカルテストは維持する。[ADR 0011](decisions/0011-simplify-android-data-menu.md)を参照。

以下は2026-10-27の設計時点の提案・調査を残す。実装済みの決定はADR 0010と後続のADR 0011を優先し、「未導入」「今回インストールしない」等は設計時の状態として読む。

## 前提と確認済みの範囲

- ユーザー確認済み：初回は旧版と同じ「PCから取り込み、サービスと履歴を選び、生成・コピーする」範囲とする。Androidでのサービス登録・編集・削除・salt追加は含めない。
- 旧版の1画面と操作順を基準にする。生成結果は表示しない。マスターと生成結果は保存しない。
- 新PC版から旧Android版への書き出しは不要。新PC版と新Android版は共通モデル・互換生成を使う。[デスクトップ設計](desktop-design.md)を参照。
- React Native＋TypeScript、Expo development client、Androidのみ、WSLでのローカルビルドは既存決定を維持する。新しい依存導入・設定変更・端末接続は今回行わない。

以下の保存・コピー・入力制限等の細部は設計案。基本範囲の決定と、実装前に確認する提案を区別する。

## 調査の根拠と限界

旧スマホ版のコミット`015b9c10f62183965aa7bb10881c42c22c33e612`の`App.js`、`util.js`、READMEを静的に確認した。[固定ソース](https://github.com/ikegami5/password_manager_sp/tree/015b9c10f62183965aa7bb10881c42c22c33e612)、[既存調査](legacy-projects.md)を参照。旧アプリ起動・スクリーンショット採取・実データ読込・旧テスト再実行は行っていない。

新構成では`apps/android/App.tsx`は確認用画面、パッケージ名は`io.github.ikegami5.newpasswordmanager`。旧`com.password_manager_sp`と別アプリなので、旧アプリの保存先・データ・署名を引き継げる前提にしない。現在の最低OSはテンプレートのAPI 24であり、利用端末との適合は未確認。

## 画面設計

### 通常の生成画面

架空データによる配置案。履歴欄はPCと違って常時表示する旧構成を維持する。

```text
┌──────────────────────────────────┐
│ パスワード生成        [データ ⋮] │
│ サービス                         │
│ [ Example service             ▼] │
│ ┌──────────────────────────────┐ │
│ │ テスト用サービスの説明       │ │
│ │ （文字列選択可能）           │ │
│ └──────────────────────────────┘ │
│ パスワードの履歴                 │
│ [ 現在のパスワード            ▼] │
│ マスターパスワード               │
│ [ ●●●●●●●●                    ] │
│ [             生成             ] │
│ クリップボードへコピーしました。 │
│ 貼り付け後は戻って消去できます。 │
│ [       パスワード消去          ] │
└──────────────────────────────────┘
```

| 要素         | 旧版の挙動                                            | 移行設計案                                                         |
| ------------ | ----------------------------------------------------- | ------------------------------------------------------------------ |
| サービス選択 | 保存順、初期は先頭                                    | 維持。配列添字でなく共通モデルのIDで管理                           |
| 説明         | 枠線付き、文字列選択可能                              | 維持。長い説明はスクロール可能にする                               |
| 履歴選択     | 最新「現在のパスワード」、以降「1つ前のパスワード」等 | 維持。saltの値は表示しない                                         |
| サービス切替 | 履歴を最新に戻す                                      | 維持。マスター欄も消去する改善案                                   |
| マスター     | 伏字、補完・自動修正を抑制。文字種・長さの検証なし    | trim・正規化しない。PC版の英数字8文字以上を無条件に追加しない      |
| 生成         | コピー後にマスター消去、フォーカス解除                | 維持。処理中は再送を無効化し、送信後すぐ入力欄を消去する案         |
| 通知         | オレンジ色のコピー・消去メッセージ                    | 位置を維持し、色と文章で状態を伝える。消去未確認を成功表示しない   |
| 手動消去     | 無条件にクリップボードを空にする                      | 自分がコピーした内容と一致するときだけ消去する改善案               |
| データ操作   | 起動時に固定パスを読み、回復UIなし                    | 「データ」メニューへ取り込み・再取り込み・直前版の復元を追加する案 |

旧版の手動消去ボタンの長文「アプリを終了する前に必ず押して下さい」は、ボタンを「パスワード消去」とし、その近くに「貼り付け後はアプリに戻って消去できます」と説明する案。通常操作は「選択→入力→生成→他アプリへ貼り付け」で保つ。

### データなし・読込エラー

初回は「PCから書き出したファイルを取り込んでください」と「ファイルを選ぶ」を表示する。サービスが0件なら生成・履歴・マスター入力を無効化し、クラッシュさせない。

読込失敗はデータなしと区別し、「保存データを読み込めませんでした」と再読込・復元の操作を表示する。解析失敗を空配列で保存しない。検証済みの現在データを利用中に取り込みが失敗した場合は、そのデータと選択を維持する。

### 端末サイズと入力操作

画面は縦1列とし、Safe Area、画面内キーボード、Androidのシステムバーを避ける。小画面・横向き・文字サイズ拡大で下部ボタンまでスクロールできるようにする。説明が長い場合も生成ボタンを操作できることを確認する。

マスターには自動大文字化・修正・候補保存を抑える指定を行い、パスワード表示切替や記憶機能は初期範囲に加えない。キーボードの表示だけで文字列を書き換えない。空白・Unicode・記号を含む既存入力の互換性を検証する。空入力や極端な入力長の拒否条件は、旧Androidに制約がないことを踏まえて実装前に確認する。

TalkBack向けにラベルと選択状態を与え、通知を読み上げられるようにする。コピーしたパスワード自体を読み上げない。キーボードの完了キーによる生成は初期範囲に追加せず、明示的な生成ボタンを使う。

## 生成・コピー・ライフサイクル

### 生成手順

1. サービス・履歴IDとデータ状態を検証し、その時点のデータ版と画面の処理世代を確定する。
2. マスターを入力欄から消去し、選択したレコードの`generatorVersion`に対応する共通コアを呼ぶ。salt・記号順・長さ・マスターを自動補正しない。
3. 成功した生成結果をクリップボードへ書き込み、完了した時点から30秒の期限を設定する。
4. コピー成功時のみ成功通知を出し、キーボードとフォーカスを閉じる。生成結果は画面の表示状態に保持しない。
5. 生成不能・コピー失敗は区別して通知する。空文字をコピーして成功扱いにする旧失敗動作は移植しない。saltや条件を自動変更しない。

生成・コピー・消去はサービス層で直列化する。再生成が失敗した場合は先行コピーの期限を取り消さない。非同期処理中にデータ更新・画面離脱が起きたら、古い世代の結果を新たにコピーしない。コピー開始後の離脱と競合した場合も、完了したコピーの消去管理を失わないようにし、実機で確認する。

### コピー内容の保護

Android 13以降のコピー表示へ秘密が出ないよう、`ClipDescription.EXTRA_IS_SENSITIVE`相当の機密フラグを付ける。[Android公式仕様](https://developer.android.com/develop/ui/views/touch-and-input/copy-paste#SensitiveContent)に基づく要件で、UIに結果を表示しないだけでは代替できない。候補のExpo Clipboardは現行公式資料に`android.isSensitive`を掲載しているが、採用するSDK 58対応版での実装・挙動は導入前に確認する。

期限管理用に直近のコピー文字列と期限をサービス層の一時メモリに持つ。保存・ログ・分析イベントには含めない。内容が変更されたことを確認したら参照を捨てる。JavaScript文字列の物理的な完全消去は保証しない。

### 状態ごとの消去

Android 10以降、通常のアプリはフォーカスがない間クリップボードを読み取れない。[Android公式仕様](https://developer.android.com/about/versions/10/privacy/changes#clipboard-data)。したがって、PCと同じ「期限に読み取り比較して消去」をバックグラウンドで保証する設計にはしない。

| 状態・イベント             | 設計案                                                                                         |
| -------------------------- | ---------------------------------------------------------------------------------------------- |
| フォーカスあり、期限到達   | 現在のテキストと最後にコピーした結果を比較し、一致時だけ空にする                               |
| 手動消去                   | 同じ比較を行って消去。成功したら期限を取り消し、保持結果を破棄                                 |
| 他アプリのコピーへ変更     | 上書きせず「クリップボードの内容が変更されています」と表示し、自分の保持結果を破棄             |
| バックグラウンド移行       | マスターを消去。貼り付けのためコピー内容は即消去しない。クリップボード読取のポーリングはしない |
| 復帰・フォーカス回復       | 期限超過なら比較・消去を試す。期限前なら元の期限を使い、30秒をやり直さない                     |
| 読取・消去が失敗           | 消去成功とは表示せず、前景で再試行・手動消去できる状態にする                                   |
| OS強制終了・プロセス再作成 | 結果と期限を永続化しない。再起動後に古いコピーの所有を推測して消去しない                       |

期限は経過時間として管理し、タイマーが予定通り動くことを前提にしない。フォーカスと前景状態は`AppState`の`change`およびAndroidの`focus`/`blur`で扱う。通知領域表示は`blur`だけの場合もあるため、マスター消去と進行中の生成結果の抑制を行う。[React Native公式資料](https://reactnative.dev/docs/appstate)。SDK固定版の型と実機挙動も確認する。

通知文は「前景では約30秒後に消去します。他アプリへ移った場合は戻って消去してください」等、保証できる範囲で示す。OS自身の自動消去に30秒保証を依存しない。常駐サービス・通知・正確なアラームを初期設計へ追加しない。バックグラウンドでも30秒以内の消去が必須なら、この案を実装する前に方式と操作上の制約を再検討する。

比較と消去の間に他アプリが書き込む競合、同一文字列の再コピー、キーボードやOSの履歴への記録は完全には制御できない。手動消去もアプリが所有を確認できる直近のコピーだけを対象とし、起動直後に無関係のクリップボードを消す操作にはしない。

## PCからの取り込み・端末保存

### 基本の運用

`PCで登録・salt追加 → 明示的にファイル書き出し → 利用者が端末へ転送 → Androidで選択・プレビュー → 確定 → 生成`を基本案とする。転送にクラウドや特定サービスを必須にしない。転送経路はユーザー運用として確認する。

Androidは取り込んだスナップショットを内部に持つ。元ファイルを継続監視せず、PC側変更時は再取り込みする。初期範囲ではAndroidからの書き出しや双方向マージを必須にしない。

### ファイル選択と取り込み手順

1. システムのファイル選択UIで、新PC版の共通形式または初回移行用の旧`data.txt`を選ぶ。選択中・取り込み中は生成と別の取り込みを止める。キャンセルなら状態を変えない。
2. 選択ファイルをアプリ専用の一時領域へコピーし、サイズ制限・文字コード・構造・形式版・生成版を検証する。拡張子だけで形式を確定しない。サイズ上限は実装前に決める。
3. 共通コアで全件検証し、件数・履歴件数・追加/削除/変更件数を表示する。saltや行原文は表示・ログ出力しない。
4. 再取り込みは全件置換と明示し、利用者の確認後に実行する。件数の減少、空ファイル、過去履歴の欠落があれば強調する。空の入力で全データを削除する操作は初期範囲で認めない案。
5. 正常な現行データを直前版バックアップに保存し、新候補を書き込み・検証・置換してから表示状態を更新する。保存失敗なら旧状態を維持する。
6. 完了後は先頭サービス・最新履歴を選び、マスターを空にする。一時コピーはキャンセル・成功・失敗時に削除し、異常終了後の残骸も起動時に片付ける。確認済みの候補を保持し、確定時に元URIを読み直さない。

ファイル選択はStorage Access Frameworkを基準とし、広域ストレージ権限や全ファイルアクセスを要求しない。Android 11以降は選択UIでも`Android/data`配下のファイルを選べないため、旧アプリの保存先を直接選ぶ手順にしない。[Android公式のファイル選択仕様](https://developer.android.com/training/data-storage/shared/documents-files)。

旧データはPC側で新形式へ取り込み・書き出しする経路を優先する。旧Androidにしかないファイルがある場合は、ユーザーが安全に取り出せる方法を端末ごとに確認してから案内する。root権限やOS制限の回避は前提にしない。

### 保存形式とバックアップ

PC設計の`formatVersion`、`generatorVersion`、サービスID、履歴ID、保存順を共通にし、新形式のsalt配列は最新順のまま読む。旧形式だけで古い順から反転する。記号順・重複・既存の長さ・履歴を変更しない。

保存先はアプリの内部永続領域とし、キャッシュ・外部共有ディレクトリ・旧アプリ領域を正本にしない。内部保存は暗号化と同義ではない。JSON・平文継続・暗号化・解除方法・鍵管理はPCと合わせて決める。OS固有の鍵保護でPCとAndroidが同じ鍵を自動共有できるとは扱わない。

直前の正常スナップショットを1世代保持する提案とする。復元は検証と件数プレビュー後に確認して行う。破損正本で正常バックアップを上書きしない。ローカルのバックアップはアンインストールや端末紛失への備えではないため、PC側の元データを保持する運用にする。

書込み・flush・置換の保証は採用ライブラリで確認する。Expo FileSystemの移動だけで原子的・永続的保存が保証されるとはみなさず、必要なら2スロットと世代管理や小さなネイティブ処理を比較し、方式を確定する。生成済み`android/`を直接修正して済ませない。

OSの自動バックアップ・端末移行でデータが外部へ複製される条件も決める。案はデータ・バックアップ・取込キャッシュをOS自動バックアップ対象から除外し、PCからの再取り込みで復旧する。`allowBackup`だけで全端末の移行を抑止できるとは扱わず、Androidの版別ルールを検証する。[Android Auto Backup公式資料](https://developer.android.com/identity/data/autobackup)。必要設定はconfig plugin等で再生成可能にし、事前確認の対象とする。

## 互換性と責務

| 層                | 担当                                                             |
| ----------------- | ---------------------------------------------------------------- |
| React画面         | 選択・入力・状態とエラー・取込確認。生成結果を表示状態へ入れない |
| アプリサービス    | 生成・コピー・期限・世代の管理、取込トランザクション、状態遷移   |
| Androidアダプター | クリップボード、ファイル選択、内部保存、前景・フォーカス通知     |
| 共通コア          | 生成版別の互換生成、旧形式解析、共通モデルとファイル検証・比較   |

Electronのmain/preload境界をReact Nativeにそのまま持ち込まない。コア・サービス・画面を分離することは、同一JSランタイム内に権限隔離があることを意味しない。秘密をReduxや永続状態、デバッグ出力、例外全文、分析サービスへ送らない。

新PC版由来は保存された`generatorVersion`に従い、Androidという理由で旧スマホ方式へ切り替えない。旧Android由来も、承認済みの剰余・乱数差異については`legacy-pc-v1`を採用し、旧Android固有の演算を再現する版は追加しない。境界入力で旧Androidと出力が異なり得ることは[ADR 0006](decisions/0006-shared-pc-generator.md)の採用判断として記録する。既知の2つの差異以外に不一致を発見した場合は、引き続き条件・影響を記録して確認する。

67件の独立した期待値に加え、過去salt、Unicodeマスター、記号順と重複、境界長、生成不能、旧スマホのNumber丸めとPCの整数演算の差を検証する。WSLのNode上での一致だけでHermes上の一致を報告しない。ハッシュ提供元もNode専用APIをコアへ持ち込まず、固定値で選定する。

| 段階              | 完了条件                                                                                                                                     |
